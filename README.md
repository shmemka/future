# Путь в будущее

Очно-заочная платформа для подростков Новосибирской области: авторские курсы, наставники, сообщество, мероприятия вживую и система цифровых жетонов. 60 самых активных участников отправляются в путешествие по региону (3–10 июня 2028).

Это работающее веб-приложение (MVP), а не макет: регистрация с ролями, база данных, курсы с уроками и проверкой заданий, запись на мероприятия, личные сообщения, модерация, админка — всё сохраняется и работает.

## Открыть

**https://shmemka.github.io/future/** — платформа работает прямо в браузере, ничего устанавливать и подключать не нужно. С телефона её можно добавить на экран «Домой» (в Safari: «Поделиться» → «На экран Домой») — она откроется как отдельное приложение.

На странице входа есть кнопки «Участник», «Наставник» и «Администратор» для входа в один клик. Под ними — «Начать демо заново»: возвращает все данные в исходное состояние (удобно перед презентацией).

Чтобы показать, как роли взаимодействуют, откройте две вкладки: в одной войдите участником, в другой наставником. Сообщения, проверка заданий, одобрение идей и жетоны появляются в соседней вкладке сразу.

### Как это устроено на GitHub Pages

GitHub Pages умеет отдавать только статичные файлы, поэтому для него собирается особая версия: те же маршруты API и та же база SQLite (в WebAssembly) работают прямо во вкладке, а данные сохраняются в браузере (IndexedDB). Следствие: у каждого устройства своя копия платформы — то, что сделано на одном телефоне, не видно на другом. Чтобы участники с разных устройств видели друг друга, нужна серверная версия (ниже), код у них общий.

Обновить сайт после изменений в коде:

```bash
npm run build:pages
git add -A && git commit -m "Обновление сайта" && git push
```

Сборка кладёт `index.html`, `404.html` и папку `assets/` в корень репозитория — Pages (Settings → Pages → Deploy from a branch → main / root) сразу показывает приложение.

## Серверная версия: быстрый старт

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Откройте http://localhost:5173. При первом запуске база создаётся автоматически и заполняется демо-данными.

### Полезные команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер API (порт 3001) и интерфейс (порт 5173) с автоперезагрузкой |
| `npm run build` | Собирает интерфейс в `dist/` |
| `npm start` | Продакшен-режим: один сервер на порту 3001 отдаёт и API, и интерфейс |
| `npm run db:reset` | Удаляет все данные и заново заполняет демо-контентом |
| `npm run build:pages` | Собирает статичную версию для GitHub Pages в корень репозитория |
| `npm run typecheck` | Проверка типов TypeScript |

## Что умеет платформа

**Участник:** регистрируется, проходит курсы (уроки, тесты с автопроверкой, задания с проверкой наставника), записывается на мероприятия, пишет в сообщество и наставникам, предлагает идеи, получает жетоны и достижения, следит за своим путём к путешествию, анонимно обращается к психологу.

**Наставник:** проверяет задания и даёт обратную связь, создаёт и редактирует свои курсы (уроки, задания, тесты), создаёт мероприятия и отмечает посещение, начисляет жетоны за командную работу, одобряет идеи, модерирует сообщество, отвечает на обращения.

**Администратор:** всё, что может наставник, плюс управление пользователями (роли, блокировка, подтверждение наставников), все курсы и мероприятия, ручное начисление и списание жетонов, журнал жетонов, статистика.

**Безопасность:** жалоба на любую публикацию, комментарий, сообщение и профиль; автоматическая блокировка телефонов, почты, ников и ссылок на соцсети; автомодерация оскорблений; правила сообщества при первом входе; анонимные обращения к психологу; участники видны другим как «Имя Ф.»; можно скрыть себя из рейтинга и запретить сообщения от участников. Рейтинг считает только образовательную активность — лайков, подписчиков и «популярности» нет.

Подробно про устройство — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что пока не подключено (честно)

Эти функции требуют внешних сервисов, поэтому в MVP их нет или они упрощены:

| Функция | Как сейчас | Что нужно для продакшена |
|---|---|---|
| Восстановление пароля, письма | Самостоятельного сброса нет. Администратор задаёт временный пароль в разделе «Пользователи» | Почтовый сервис (SMTP, например Unisender или Яндекс 360) |
| Мгновенные сообщения | Чат обновляется каждые 5 секунд | WebSocket (например, Socket.IO) |
| Загрузка фото и файлов | Аватар — цвет и эмодзи, без загрузки картинок | Объектное хранилище (S3-совместимое: Yandex Object Storage, Selectel) |
| Push-уведомления на телефон | Уведомления только внутри платформы | Web Push или Telegram-бот |
| Модерация оскорблений | Базовый словарь: подозрительный текст уходит на ручную проверку | Сервис модерации текста или ML-классификатор |
| Согласие родителей для младше 14 | Галочка при регистрации | Юридически оформленное согласие (бумажное или через Госуслуги) |

**Персональные данные.** Платформа хранит данные несовершеннолетних. По 152-ФЗ данные граждан РФ должны храниться на серверах в России, а проекту нужно уведомить Роскомнадзор как оператору персональных данных. Перед запуском с реальными подростками стоит согласовать это с юристом.

## Как выложить серверную версию

Когда понадобится общая база для всех участников, подойдёт любой VPS (Timeweb Cloud, Selectel, Yandex Cloud) с Docker:

```bash
docker build -t put-v-budushchee .
docker run -d -p 80:3001 -v $(pwd)/data:/app/data -e JWT_SECRET=длинная-случайная-строка put-v-budushchee
```

Папка `data/` с базой должна быть на постоянном диске, иначе данные сотрутся при перезапуске. Для HTTPS поставьте перед приложением Caddy или Nginx.

## Стек

React 19 + TypeScript + Vite + Tailwind CSS 4 · Express 5 · SQLite (better-sqlite3) · сессии на JWT в httpOnly-cookie, пароли — bcrypt · валидация — zod. Шрифты Unbounded и Onest подключены локально.
