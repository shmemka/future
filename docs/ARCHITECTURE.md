# Архитектура платформы «Путь в будущее»

## Общая схема

```
Браузер (React SPA)  ──/api──▶  Express-сервер  ──▶  SQLite (data/future.db)
        ▲                          │
        └──── в продакшене сервер же отдаёт собранный интерфейс из dist/
```

Для GitHub Pages та же схема собирается целиком в браузер (`npm run build:pages`):

```
React SPA  ──api.ts──▶  client/src/offline/engine.ts  ──▶  те же маршруты server/src/routes  ──▶  sql.js (SQLite в WebAssembly)
                                                                                               └─▶ сохранение в IndexedDB
```

Маршруты написаны один раз. В браузере Express заменяет маленький роутер (`offline/express-shim.ts`), база — sql.js, сессия — sessionStorage/localStorage. Запросы выполняются по очереди, после каждого изменения база сохраняется, а другие вкладки получают сигнал и обновляют данные.

Одно приложение, один процесс, один файл базы. Этого хватает на сотни активных участников. Когда понадобится больше — см. раздел «Как масштабировать».

## Структура проекта

```
shared/constants.ts      Справочники для сервера и клиента: направления, уровни, жетоны, достижения, параметры путешествия
server/src/
  index.ts               Точка входа: middleware, подключение роутов, раздача фронтенда
  schema.sql             Схема БД
  db.ts                  Подключение к SQLite и хелперы запросов
  seed.ts, seed-content.ts  Демо-данные: курсы с уроками, мероприятия, пользователи, обсуждения
  lib/auth.ts            Сессии, пароли, проверка ролей
  lib/progress.ts        Жетоны, достижения, уведомления, история активности
  lib/safety.ts          Фильтр контактов и автомодерация
  routes/                API по доменам: auth, me, courses, events, community, safety (+ модерация и админка), public
client/src/
  App.tsx                Маршруты и защита страниц по ролям
  components/            Оболочка, UI-кит, карточки, редактор мероприятий, блок задания
  pages/                 Страницы
  lib/                   API-клиент, сессия, форматирование дат (время — по Новосибирску)
```

## Роли и права

| Действие | Участник | Наставник | Админ |
|---|:-:|:-:|:-:|
| Курсы, задания, мероприятия, сообщество, сообщения | ✓ | ✓ | ✓ |
| «Мой путь», участие в рейтинге | ✓ | | |
| Проверка заданий | | свои курсы | все |
| Создание и редактирование курсов | | свои | все, + удаление |
| Создание мероприятий | | ✓ (редактирует свои) | ✓ + удаление |
| Отметка посещения | | ✓ | ✓ |
| Жетоны за командную работу | | до 30 за раз | любые суммы и категории |
| Модерация публикаций, жалобы, обращения | | ✓ | ✓ |
| Блокировка аккаунтов, роли, подтверждение наставников | | | ✓ |

Наставник регистрируется сам, но аккаунт активирует администратор. Права проверяются на сервере (`requireRole` в `lib/auth.ts`); интерфейс только скрывает недоступное.

## Модель данных

- **users** — участники, наставники, админы. Интересы — JSON-массив направлений. Настройки приватности: `show_in_rating`, `allow_messages`.
- **courses → lessons, tasks** — курс, его уроки (простая разметка) и задания двух типов: `text` (проверяет наставник) и `quiz` (проверяется автоматически, правильные ответы участнику не отдаются).
- **enrollments, lesson_progress, submissions** — запись на курс, пройденные уроки, ответы на задания со статусами `pending / approved / revision`.
- **events, event_registrations** — мероприятия и записи со статусом `registered / attended`. Время хранится в UTC, показывается по Новосибирску.
- **token_tx** — журнал жетонов. Баланс — сумма. Поле `ref` (например, `task:12`) с уникальным индексом не даёт начислить дважды за одно действие.
- **user_achievements** — открытые достижения; условия считаются по фактическим данным (`evaluateAchievements`).
- **channels, posts, comments, post_supports** — сообщество. Посты: `discussion / idea / question`, статусы `published / pending / hidden / rejected`.
- **messages** — личные сообщения.
- **reports, help_requests** — жалобы и обращения за помощью (в том числе анонимные).
- **activity, notifications** — история действий пользователя и уведомления.

## Система мотивации

| За что | Жетонов | Как начисляется |
|---|---|---|
| Тест в курсе | 10 | Автоматически при всех верных ответах |
| Задание с ответом | 15–20 | Когда наставник зачёл |
| Курс целиком | 30–45 | Автоматически, когда пройдены все уроки и зачтены все задания |
| Мероприятие | 15–35 | Когда наставник отметил посещение (с момента начала встречи) |
| Командная работа | до 30 | Вручную наставником |
| Идея или проект | 20 | Когда наставник одобрил идею |

Уровни-«станции»: Перрон (0) → Посадка (50) → Первый перегон (120) → Узловая станция (200) → Экспресс в будущее (300). Порог путешествия — 300 жетонов, мест — 60, рейтинг закрывается 25 мая 2028. Все числа — в `shared/constants.ts`.

## Ключевые сценарии

1. **Первый вход участника:** регистрация → правила сообщества (достижение «Свой человек») → главная с рекомендациями по интересам.
2. **Обучение:** запись на курс → урок → «Урок пройден» → тест (можно пересдавать) → задание → наставник зачитывает или возвращает с комментарием → курс завершён → жетоны и достижение.
3. **Мероприятие:** запись в календаре → наставник на месте отмечает пришедших → жетоны.
4. **Идея:** участник публикует идею → она на модерации (видна только автору) → наставник одобряет → публикация + 20 жетонов.
5. **Помощь:** раздел «Безопасность» → обращение психологу, можно анонимно → ответ приходит в уведомления.
6. **Жалоба:** кнопка на сообщении → модератор видит контент в контексте → скрывает, при необходимости админ блокирует автора → заявитель получает ответ.

## Безопасность

- Пароли — bcrypt; сессия — подписанный JWT в httpOnly-cookie на 30 дней; защита от перебора пароля (10 попыток за 5 минут).
- Все входные данные проверяются zod-схемами на сервере.
- Фильтр контактов (`lib/safety.ts`) отклоняет телефоны, почту, ники и ссылки на соцсети в постах, комментариях, сообщениях и профиле.
- Подозрительные слова отправляют пост или комментарий на ручную проверку; в личных сообщениях участника такое сообщение не отправляется.
- Участники видят друг друга как «Имя Ф.», почту видит только администратор.
- Обращения с флагом «анонимно» показываются специалисту без имени и города.

## Как масштабировать

- **Больше пользователей:** заменить SQLite на PostgreSQL. Все запросы собраны в `routes/` и написаны на стандартном SQL — перенос механический. Можно подключить ORM (Drizzle или Prisma).
- **Реальное время:** добавить WebSocket для сообщений и уведомлений вместо опроса.
- **Файлы:** S3-совместимое хранилище для аватаров, фото мероприятий и альбома воспоминаний.
- **Новые направления, уровни, достижения:** правятся в `shared/constants.ts`; условия достижений — в `evaluateAchievements`.
- **Мобильное приложение:** API уже отделён от интерфейса, его можно переиспользовать.
